# Segment 10: Flexural Member (Beams & Plate Girder) — Claude Review
**Date:** 2026-08-01 | **Scope:** frontend/src/modules/flexuralMember/{onCantilever,purlin,simplySupportedBeam,plateGirder}, backend/apps/modules/flexure_member | **Status:** Reviewed (read-only)

## Summary

This module is architecturally the most sophisticated of those reviewed so far — Plate Girder adds a real-time PSO (particle swarm optimization) flow over Django Channels/Celery with client-side batched playback, on top of the same registry/adapter pattern used elsewhere. The registry wiring is clean (exactly 4 auto-discovered submodules matching the 4 slugs allowlisted in `options()` — no orphan-route problem like Segment 9's shear_connection). The main issue is a large spread in backend input-validation rigor across the 4 submodules: Plate Girder validates types and numeric convertibility thoroughly, Simply Supported Beam and On-Cantilever only check key *presence* (not emptiness/type), and Purlin's `validate_input` is a complete no-op (`pass`). There's also the by-now-repo-wide dead-`OutputDock.jsx` pattern (confirmed here for the 7th time) and ~250 lines of near-identical CAD-generation/output-formatting boilerplate duplicated across the 3 non-PSO adapters.

## Red Flags (security / correctness-critical)

- **Purlin backend performs zero input validation** — `backend/apps/modules/flexure_member/submodules/purlin/adapter.py:51-56` — `validate_input()` is `pass`, a complete no-op, despite `get_required_keys()` declaring 13 required keys just above it. `create_from_input` (line 138) does default-fall-back for every field (`input_values.get(...) or <default>`), so missing/empty/malformed inputs never raise a clean `MissingKeyError`/`InvalidInputTypeError` — they silently fall through to hardcoded defaults (e.g. `moment_yy = input_values.get(...) or 0.0`) or propagate into `osdag_core` and fail with an opaque exception. Concrete failure: a request with `Member.Profile` missing entirely still reaches `set_input_values()` — if it's not caught by the `if not sec_profile: raise ValueError(...)` guard (which only fires on complete absence, not on a type-mismatched value), a malformed request produces a confusing 500 instead of a clean 400.

## Bugs

- **`validate_input` rigor varies wildly across the 4 submodules with no shared contract** — `backend/apps/modules/flexure_member/submodules/{on_cantilever,simply_supported_beam,plate_girder}/adapter.py` — On-Cantilever's `validate_input` (on_cantilever/adapter.py:41-52) checks only 5 of the 11 keys listed in its own `get_required_keys()` (skips `Material`, `Member.Material`, `Flexure.Type`, `Cantilever.Support`, `Cantilever.Top`, `Member.Profile` entirely). Simply Supported Beam's `validate_input` (simply_supported_beam/adapter.py:50-55) checks all 16 declared keys but only via `contains_keys()`, which — per `backend/apps/core/utils/validation.py:19-26` — only checks key *presence*, not emptiness or type; an empty string for `Load.Shear` passes cleanly and reaches `osdag_core`. Plate Girder (plate_girder/adapter.py:105-186) is the only submodule that additionally type-checks and float-converts every numeric key. Net effect: the same class of "empty/malformed load value" bug flagged in Segment 7 (Base Plate) exists here too, and it's inconsistent module-to-module within the very same parent module — a maintainer fixing it in one submodule has no reason to think the sibling submodules need the same fix.
- **On-Cantilever's CAD model literally reuses the Simply-Supported-Beam shape generator** — `backend/apps/modules/flexure_member/submodules/on_cantilever/adapter.py:273-276` — `create_cad_model()` calls `cld.createSimplySupportedBeam()` with the comment "cantilever beam shape is structurally similar - same I-section geometry." This is explicit/intentional, not a copy-paste accident, but it means the 3D CAD viewer for a cantilever beam does not visually reflect the fixed/free support condition that's core to what a cantilever *is* — worth flagging to a domain expert to confirm this is an acceptable simplification rather than a visual-accuracy gap users would notice.

## Code Quality / Improvement Suggestions

- **Confirmed repo-wide dead-`OutputDock.jsx` pattern (7th occurrence)** — `frontend/src/modules/flexuralMember/simplySupportedBeam/components/SimplySupportedBeamOutputDock.jsx` — grep confirms this file is never imported anywhere; `SimplySupportedBeam.jsx` renders via `EngineeringModule` + `simplySupportedBeamOutputConfig` directly, bypassing this component entirely, matching the identical dead-output-dock pattern already found in Segments 5, 6, 7, 8, and 9. Notably, only 1 of the 4 submodules here (`simplySupportedBeam`) even has an `OutputDock.jsx` file — `onCantilever`, `purlin`, and `plateGirder` don't — suggesting this leftover component is only present where a pre-refactor version happened to exist, not a pattern anyone actively maintains. This is now confirmed universal across every module segment reviewed (5 through 10): worth a single repo-wide cleanup PR deleting all `*OutputDock.jsx` files rather than fixing per-module.
- **~250 lines of near-identical CAD-generation/output-formatting code duplicated across 3 adapters** — `backend/apps/modules/flexure_member/submodules/{on_cantilever,purlin,simply_supported_beam}/adapter.py` — `generate_output()` (collect `spacing`/`output_values`/`detail`/`detailing`, format `TextBox` params, reverse logs) and `create_cad_model()` (BRep_Builder/TopoDS_Compound assembly, `file_storage/cad_models` path construction, BREP+STL write with identical try/except/print-traceback scaffolding) are copy-pasted near-verbatim across all three. A shared helper in `apps/core/utils` (already home to `cad_helpers.py`/`module_helpers.py`) would remove this duplication and ensure future fixes (e.g. the STL-write silent-failure pattern) land everywhere at once instead of three places independently.
- **Inconsistent `print()`-based debug logging** — e.g. `on_cantilever/adapter.py:176-179,232-233`, `purlin/adapter.py:393-394`, `simply_supported_beam/adapter.py:179-180,85` — same pattern already flagged repo-wide in Segment 1; every adapter here prints request internals (including full `design_dict` keys) to stdout rather than using `logging`. The Plate Girder Celery task (`plate_girder/tasks.py`) is the one exception — it uses proper `logger.info`/`logger.error` throughout, showing the pattern is known and achievable, just not applied consistently.
- **`INFLUXDB_TOKEN` hardcoded default duplicated in a second file** — `backend/apps/core/consumers.py:47` (`token = os.getenv("INFLUXDB_TOKEN", "osdag-super-secret-token")`) — this is the same hardcoded fallback already flagged as a Segment 1 red flag at `backend/config/settings.py:284`; it's worth noting the literal string is duplicated (not imported from settings), so fixing it in one place won't fix the other.

## Minor / Nits

- **Purlin's PSO-adjacent hook is mounted globally, not lazily** — `frontend/src/modules/shared/components/EngineeringModule.jsx:388-415` — `usePlateGirderOptimization` is unconditionally called for every module type (Tension Members, Base Plate, etc.), not just Plate Girder. Per the hook's own internals (`useWebSocketOptimization`), it stays fully idle until `startPsoOptimization` is invoked, so this isn't a functional bug — just extra hook/state overhead mounted on every single engineering module page for a feature only one module uses.
- **Core-library typos silently reverse-mapped in the adapter** — `on_cantilever/adapter.py:112-122,132-140` — the adapter maintains explicit dictionaries to translate correctly-spelled frontend strings (e.g. `"Continuous, with lateral restraint..."`, `"Torsional restraint"`) into `osdag_core`'s misspelled internal constants (`"Continous, ..."`, `"Torsional rwstraint"`). This works today but is a landmine: if `osdag_core` ever fixes its own typos (out of scope here, but plausible), these mapping dicts silently start passing through the *old* misspelled value as a literal string with no match, defaulting to the fallback branch.
- **`plate_girder/adapter.py:37-39`** — dead code: `sys.stdout` is redirected to `os.devnull` and then immediately reset two lines later, with no code executed in between. Harmless but confusing — looks like a leftover from debugging that never actually suppressed anything.

## Positive Notes

- **Plate Girder's PSO Celery task (`tasks.py`) is genuinely well-engineered** — proper structured `logger` usage throughout (not `print`), particle batching/throttling (`SEND_INTERVAL`, `MAX_PARTICLES_PER_BATCH`) to avoid flooding the WebSocket, a heartbeat mechanism so the client can distinguish "still running" from "silently dead," `_sanitize_for_channels` correctly handling numpy scalar/array serialization before sending over Channels, and best-effort CAD generation wrapped so a CAD failure never fails the whole optimization run.
- **PSO task revocation on client disconnect** — `backend/apps/core/consumers.py:163-176` (`PSOOptimizationConsumer.disconnect`) — correctly calls `app.control.revoke(self.task_id, terminate=True)` when the WebSocket drops mid-optimization, preventing zombie Celery workers from continuing to burn CPU on an abandoned request. This is a detail that's easy to skip and wasn't present in some other async flows reviewed.
- **`usePlateGirderOptimization` hook is cleanly memoized** — `frontend/src/modules/shared/hooks/usePlateGirderOptimization.js` — every callback is properly wrapped in `useCallback` with correct dependency arrays, and cleanup (`stopPsoPlayback`/`disconnect`) is correctly wired to the unmount effect (lines 293-298), avoiding the kind of stale-closure/leaked-interval bugs flagged elsewhere in Segment 4.
- **Registry/URL wiring for this module has no orphaned-route problem** — verified all 4 registered submodule slugs (`on-cantilever`, `plate-girder`, `purlin`, `simply-supported-beam`) exactly match the 4 slugs explicitly handled in `FlexureMemberViewSet.options()` (`backend/apps/modules/flexure_member/views.py`), unlike Segment 9's shear_connection where an orphaned `cantilever` submodule was silently reachable outside its allowlist.
